# Per-item icons (2026-11-07)

`items.icon_key` stores a key of the icon registry (`js/icon-registry.js`), chosen from an internal gallery
(`js/item-icon-gallery.js`). No upload, no URL, no SVG or HTML: the table check `items_icon_key_check` accepts only
`^(item|potion|plant|inventory|slot)\.[a-z0-9-]+$`, and `_item_icon_key` gives the friendly "Choose an icon from the gallery".

Resolution when an item is drawn: 1. the item's own key (if the browser's gallery knows it) → 2. the category default
(`ITEM_ICONS` by kind, shield, magic, container) → 3. the generic icon (the icons.js fallback chain). Existing category
defaults and existing items are unchanged (all `icon_key` NULL).

Gallery (35 keys, each with a text label): potions (generic, healing, blue, poison, acid, fire, pink, flask, bottle, empty),
plants (herb sprig, leaf / grass, flower, wildflowers, mushroom, root / thorny vine, seed head, berries), crystal / resin, gem,
ingredient (mortar), cauldron, weapon, tool, armor, magic, scroll, wand, amulet, bandage, candle, container, treasure, key, book.

New assets (`assets/icons/plants/*.webp`, `assets/icons/potions/flask.webp`, `bottle.webp`) come from the project's own icon
pool `../icons` (same illustrated family); see `ICON_ASSET_INVENTORY.md`. The registry is regenerated by
`scripts/local/build_icon_registry.py` (folder `plants` added; aliases `inventory.herbs`, `inventory.potion`).

An icon change is display-only: no rules recalculation; the homebrew update invalidates the catalog item cache only.
The picker is a radio group (arrow keys), each option has a visible label, the selected option has a visible outline.
