## Rules

1. **Index what is queried, filtered by RLS, or touched by an FK action on a large table.**
   `inventory_items`, `inventory_events` and `owned_assets` grow with play; they get indexes for `inventory_id`, the FK
   `ON DELETE` paths (`item_id`, `container_item_id`, `inventory_item_id`) and the owner relations.
2. **No duplicates of primary keys / unique constraints.** `character_equipment (character_id, …)`, its unique `inventory_item_id`,
   and `inventory_item_modifiers (inventory_item_id, …)` are already covered.
3. **No secondary indexes on catalog and lookup tables.** ~1.2k items and tens of lookup rows; the client loads the catalog once and
   filters it locally. A sequential scan is cheaper than an index lookup at this size, and these rows are not deleted by clients.
4. **Deferred, with a trigger:** `pg_trgm` and full-text search on `items.name` when search moves to the server;
   `items (kind_id)`, `(category_id)`, `(owner_id)`, `(campaign_id)` when the catalog passes ~10k rows (homebrew);
   `inventory_events (created_at)` with a retention job; `inventory_events (actor_id)` with a per-user audit screen.

`pg_trgm` is therefore not installed by the migrations anymore (nothing depends on it).

## Kept indexes

| Index | Why |
|---|---|
| `inventory_items_inventory_idx (inventory_id)` | every inventory read, RLS `can_read/can_write_inventory`, auto-merge lookup |
| `inventory_items_item_idx (item_id) partial` | `ON DELETE RESTRICT` check when a homebrew item is deleted |
| `inventory_items_container_idx (container_item_id) partial` | `ON DELETE SET NULL`, container views |
| `inventory_events_inventory_idx (inventory_id, created_at desc)` | history per inventory, RLS, cascade |
| `inventory_events_item_idx (inventory_item_id) partial` | `ON DELETE SET NULL` on every hard delete (last potion used) |
| `inventories_campaign_idx (campaign_id) partial` | party stash / shop / NPC, cascade from campaigns |
| `owned_assets_character_idx`, `owned_assets_campaign_idx` | RLS + cascades |
| `inventories_party_stash_uniq`, `equipment_slot_rules_uniq` | business rules (unique) |
| `legacy_inventory_review_character_idx` | RLS of the review table |

Re-check with `EXPLAIN (ANALYZE)` on production-sized data before adding any deferred index.
